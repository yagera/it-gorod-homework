# ДЗ ML-стажировки (ДИТ Москвы)

Две задачи, сдаются два CSV (`task-1.csv`, `task-2.csv`), дедлайн 22.11.2026, 12:00.

| Задача | Что | Метрика |
|---|---|---|
| T1 | прогноз `yearly_cv_processed` на 2024 по 505 департаментам | MAPE |
| T2 | классификация муниципальных НПА по коду `NNN.NNN.NNN` (58 классов) | Macro-F1 |

Текущее состояние: T1 — планка «ratio отдела за 2023 × `active_projects_count`» (`docs/DECISIONS.md`, запись 10); T2 — TF-IDF (word + char) + LinearSVC, C=1, 2000 символов (`outputs/task-2.csv`, записи 15–18). Подробности и оговорки — `docs/EXPERIMENTS.md`, `docs/DECISIONS.md`.

## Установка и данные
```
make install          # uv sync (в т.ч. группа dl: torch и др.)
```
Данные не в git: положить выданные файлы в `data/raw/task/` (условия), `data/raw/task1/`, `data/raw/task2/`.

## Команды
```
make t1                  # → outputs/task-1.csv
make t2-prepare-smoke    # усечённые тексты → data/processed
make t2-smoke            # → outputs/task-2.smoke.csv (только проверка формата)
make t2                  # → outputs/task-2.csv (fit на всём train)
make t2-experiment | t2-tune | t2-tune2 | t2-stability   # эксперименты T2 (долго, пишут в outputs/)
make validate            # формат обоих сабмишнов против sample_submission
make check-time-split    # порядок фолдов T1 и отсутствие будущих лет/таргета 2024 в сырых данных (утечки через признаки не ловит)
make lint | test | ci    # ruff, pytest, оба сразу
```
Все команды — обёртки над CLI `uv run itgorod …`. Тесты работают на синтетике и не требуют `data/`.

## Ограничения оценки
- **T2: оценка включает сигнал порядка сбора данных.** Классы сконцентрированы по датам выгрузки (вероятно, данные выгружались партиями по классам): дата выгрузки (в шапке документа) сильно связана с классом — 56 из 58 классов имеют ≥95% строк в одной из 4 групп дат, мода класса по дате выгрузки даёт accuracy 0,76 при majority 0,35 (Macro-F1 такого правила 0,15) (`docs/DECISIONS.md`, записи 17–18). OOF Macro-F1 финалиста 0,84 (основная схема) / 0,80 (контрольная) включает этот сигнал; без номера и дат ориентир около 0,70–0,75 (абляция «без номера и дат»: 0,7525 / 0,7033; она убирает заодно дату акта и номер, поэтому оценка грубая). Распределение дат выгрузки в test совпадает с train, поэтому на test структура, скорее всего, доступна так же, но оценки на test нет. Подмена даты выгрузки случайной в valid (модель обучена с настоящими датами) снижает Macro-F1 финалиста до 0,65 / 0,59 (−0,19 / −0,22 при подстановке дат с частотами train), у 38 из 58 классов (основная схема) F1 падает более чем на 10 п.п.: модель сильно опирается на дату, но это чувствительность к ложной дате, а не оценка «без даты».
- **Выбор по той же CV.** Тип усечения и C выбирались по основной схеме на тех же данных, поэтому оценка победителя оптимистична; σ по фолдам (≈0,01) сопоставима с разностями многих конфигураций.
- **Схема по группам дат вырождена** (классы почти не пересекаются между группами): Macro-F1 ≈ 0,007 у всех трёх проверенных вариантов (LinearSVC C=1), она не измеряет вклад шапки.
- **Не проверено:** почти-дубли документов, разложение «номер / дата акта / дата выгрузки», причина сдвига доли классов в декабре 2025. Полный список — «Известные ограничения» в `docs/DECISIONS.md`.

## Опциональные эмбеддинги (в сабмишн не используются)
Проверялись эмбеддинги `intfloat/multilingual-e5-base` как дополнительные признаки T2; результат — отрицательный (`docs/DECISIONS.md`, записи 19–20).
- **Запуск** (нужен GPU и группа `dl`; для быстрой загрузки модели — `hf auth login`, токен в код и файлы не попадает):
  ```
  make t2-embed        # кодирует train+test (≈8 мин на RTX 2060 SUPER, 8 ГБ) → data/cache/ (вне git)
  make t2-embed-eval   # OOF LogisticRegression и бленд с TF-IDF SVC → outputs/t2_embed_eval_*.csv
  ```
  Первый запуск `t2-embed-eval` дополнительно считает OOF TF-IDF SVC (≈20 мин, кэш в `outputs/oof_*.npy`). Число итераций LR: `uv run itgorod t2 embed-eval --max-iter 1500`.
- **Результат:** OOF Macro-F1 эмбеддингов 0,62 / 0,57 (основная / контрольная схемы) против 0,84 / 0,80 у TF-IDF SVC; бленд даёт прирост +0,0018 / +0,0014 при σ = 0,0086, то есть прироста нет. Эмбеддинги не приняты.
