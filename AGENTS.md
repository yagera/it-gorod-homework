# AGENTS.md

## Цель и сдача
ДЗ ML-стажировки (ДИТ Москвы). Две задачи, обе обязательны. Сдаются **только два CSV**:
`task-1.csv` и `task-2.csv` в одной папке на Яндекс.Диске (+ файл «Общение с ИИ» со ссылками
на диалоги). **Дедлайн: 22.11.2026, 12:00.** EDA, код и документация живут в репозитории.

| Задача | Что | Метрика | Формат сабмишна |
|---|---|---|---|
| T1 | прогноз `yearly_cv_processed` на 2024 по 505 департаментам | MAPE | `department_id,yearly_cv_processed`, 505 строк, значения > 0, порядок id как в sample |
| T2 | классификация НПА по `code` (58 классов, иерархия `NNN.NNN.NNN`) | Macro-F1 | `row_id,code`, 10001 строка, `row_id` как в sample, коды только из train |

## Структура
`src/itgorod/` (пакет, CLI `itgorod`), `configs/` (YAML), `tests/` (синтетика, без `data/`),
`notebooks/` (только EDA), `docs/` (AI_LOG, EXPERIMENTS, DECISIONS, specs, plans),
`data/raw` (выдано, не в git), `data/processed` (кэш усечённых текстов T2, не в git),
`outputs/` (сабмишны, не в git).

Команды Makefile (появятся в Task 7 плана): `make install | lint | format | test | t1 |
t2-prepare-smoke | t2-smoke | validate | check-time-split | ci`.

## Правила валидации
- **T1 — только по времени.** Фолды в `configs/t1.yaml` (`split.folds`: ≤2021→2022, ≤2022→2023).
  Случайные K-fold и перемешивание запрещены.
- **Правило утечки (A):** для года Y можно использовать все признаки года Y и любые данные
  лет < Y (включая лаги таргета). Нельзя: таргет года Y и любые данные лет > Y. Агрегаты по
  отделу/стеку считаются только по train-годам фолда.
- **T2 — TBD.** Схема валидации (stratified или по дате из шапки документа) не фиксируется,
  пока не проверено, разбит ли test по времени относительно train. После проверки правило
  записывается сюда и в `docs/DECISIONS.md`.

## Жёсткие запреты
- Не читать `.env*`. Не коммитить `data/`, `outputs/`, секреты.
- `code` (T2) — всегда `str` (`dtype=str`), иначе теряются ведущие нули.
- Не грузить тексты T2 целиком: parquet только батчами / нужными колонками; усечённые
  тексты кэшируются в `data/processed`.
- Smoke- и плейсхолдер-результаты не выдавать за бейзлайн (в `EXPERIMENTS.md` — типы
  `smoke` / `placeholder`).
- Git: коммит только когда пользователь написал «коммить» на чекпойнте; push — только по
  отдельной команде. В сообщения коммитов и PR не добавлять строки атрибуции.
- Не добавлять Hydra, MLflow, DVC, Docker (причина — `docs/DECISIONS.md`).

## Definition of Done
1. `make lint` и `make test` зелёные.
2. `validate-submission` проходит для каждого затронутого сабмишна.
3. `time-split-check` пройден при любом изменении T1 (признаки, валидация).
4. Был прогон → строка в `docs/EXPERIMENTS.md`.
5. Принято решение → запись в `docs/DECISIONS.md`.
6. После каждого шага → запись в `docs/AI_LOG.md` через скилл `log-step`.
