# ДЗ ML-стажировки (ДИТ Москвы)

Две задачи, сдаются два CSV (`task-1.csv`, `task-2.csv`), дедлайн 22.11.2026, 12:00.

| Задача | Что | Метрика |
|---|---|---|
| T1 | прогноз `yearly_cv_processed` на 2024 по 505 департаментам | MAPE |
| T2 | классификация муниципальных НПА по коду `NNN.NNN.NNN` (58 классов) | Macro-F1 |

Текущее состояние: T1 — планка «ratio отдела за 2023 × `active_projects_count`» (`docs/DECISIONS.md`, запись 10); T2 — TF-IDF (word + char) + LinearSVC, C=1, 2000 символов (`outputs/task-2.csv`, записи 15–18). Подробности и оговорки — `docs/EXPERIMENTS.md`, `docs/DECISIONS.md`.

## Установка и данные
```
make install          # uv sync (в т.ч. группа dl: torch и др.)
```
Данные не в git: положить выданные файлы в `data/raw/task/` (условия), `data/raw/task1/`, `data/raw/task2/`.

## Команды
```
make t1                  # → outputs/task-1.csv
make t2-prepare-smoke    # усечённые тексты → data/processed
make t2-smoke            # → outputs/task-2.smoke.csv (только проверка формата)
make t2                  # → outputs/task-2.csv (fit на всём train)
make t2-experiment | t2-tune | t2-tune2 | t2-stability   # эксперименты T2 (долго, пишут в outputs/)
make validate            # формат обоих сабмишнов против sample_submission
make check-time-split    # порядок фолдов T1 и отсутствие будущих лет/таргета 2024 в сырых данных (утечки через признаки не ловит)
make lint | test | ci    # ruff, pytest, оба сразу
```
Все команды — обёртки над CLI `uv run itgorod …`. Тесты работают на синтетике и не требуют `data/`.

- `outputs/` — сабмишны (не в git); `data/processed/` — кэш текстов T2 (не в git).
- `AGENTS.md` — правила проекта (метрики, валидация, запреты, Definition of Done); `CLAUDE.md` — модели и агенты.

## Ограничения оценки
- **T2: оценка включает сигнал порядка сбора данных.** Классы сконцентрированы по датам выгрузки (вероятно, данные выгружались партиями по классам): дата выгрузки (в шапке документа) почти определяет класс — 56 из 58 классов имеют ≥95% строк в одной группе дат, дата выгрузки сама по себе даёт accuracy 0,76 при majority 0,35 (`docs/DECISIONS.md`, записи 17–18). OOF Macro-F1 финалиста 0,84 (основная схема) / 0,80 (контрольная) включает этот сигнал; без номера и дат ориентир около 0,70–0,75 (абляция «без номера и дат»: 0,7525 / 0,7033; она убирает заодно дату акта и номер, поэтому оценка грубая). Распределение дат выгрузки в test совпадает с train, поэтому на test структура, скорее всего, доступна так же, но оценки на test нет.
- **Выбор по той же CV.** Тип усечения и C выбирались по основной схеме на тех же данных, поэтому оценка победителя оптимистична; σ по фолдам (≈0,01) сопоставима с разностями многих конфигураций.
- **Схема по группам дат вырождена** (классы почти не пересекаются между группами): Macro-F1 ≈ 0,007 у всех трёх проверенных вариантов (LinearSVC C=1), она не измеряет вклад шапки.
- **Не проверено:** почти-дубли документов, разложение «номер / дата акта / дата выгрузки», причина сдвига доли классов в декабре 2025. Полный список — «Известные ограничения» в `docs/DECISIONS.md`.
